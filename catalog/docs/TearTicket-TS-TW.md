# TearTicket
**Registry**: `TearTicket-TS-TW` · **Deps**: `motion@^12.23.12` · **Files**: `TearTicket/TearTicket.tsx`
**What it does** — A card shaped like a ticket with a perforated stub; grab the stub and pull and the paper stretches, tears fibre by fibre along the perforation, then the stub tumbles away under gravity. Pull too little and it springs back intact; the card tilts and parallaxes with the pointer.
**Props** — `children` / `stub` (ReactNode) — body and stub content; `image` / `imageAlt` (string) — artwork behind the body; `width` (number, 460), `height` (number, 250), `stubSize` (number, 150) — fixed geometry; `orientation` (`horizontal`|`vertical`, horizontal) — which edge tears; `holes` (number, 12), `holeSize` (number, 6), `notch` (number, 3), `roughness` (number, 0) — perforation cut; `tearAngle` (number, 30), `stretch` (number, 30), `resistance` (number, 0.45) — how far and how stubbornly it pulls; `torn` / `defaultTorn` / `onTear` — controlled or uncontrolled state.
**Motion** — Pointer drag runs a small physics sim (gravity 2400, hinge and spin, spring return) while motion/react handles the tilt and parallax; each perforation bridge snaps at its own threshold and the torn fibres become SVG paths. Reduced motion tears instantly. Triggered only by grab-and-pull, or keyboard activation.
**Cost** — `motion` (~30–40 KB gzip), ~27 KB source, a fixed-pixel layout scaled to fit, plus two SVG outlines and one clip-path per card — clip-path on a large element is GPU-composited but can be expensive while dragging. Client-only physics; no meaningful server render beyond the static card.
**Fit for ARKRETE** — no fit. Tearing a perforated stub is a ticket-and-coupon metaphor; on an interiors site it reads as a promotion, and a fixed 460×250 card fights the full-bleed room photography.
**Verdict** — skip — a very good paper trick looking for a ticketing product, not a fit-out portfolio.
