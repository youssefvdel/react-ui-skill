# PixelSwap
**Registry**: `PixelSwap-TS-TW` · **Deps**: none · **Files**: `PixelSwap/PixelSwap.tsx`
**What it does** — Transitions between two content layers using an animated mosaic mask of scaling and rotating pixel tiles. The transition sweeps across the surface in waves following pointer location, center-out, spiral, or directional patterns.
**Props** — `firstContent` / `secondContent` (ReactNode) — the front and back content layers to transition between; `pattern` (string, 'pointer') — wipe progression order: pointer, random, center, edges, left-to-right, spiral, etc.; `pixelSize` (number, 48) — dimensions of individual mosaic tiles in pixels; `gap` (number, 0) — spacing between adjacent pixel tiles; `pixelRadius` (number, 0) — corner rounding on mosaic tiles; `pixelSpin` (number, 0) — degrees of rotational spin applied to tiles during transition; `duration` / `pixelDuration` (number, 400 / 350) — sweep window and individual tile spring time in ms; `trigger` ('hover' | 'click' | 'none', 'hover') — event that triggers the swap between front and back views.
**Motion** — A custom second-order spring integrator running in requestAnimationFrame calculates per-tile scale and rotation. On every frame, it constructs an SVG path string containing hundreds of polygon paths and updates `layer.style.clipPath = path('...')`. Reduced motion skips the spring loop and toggles layer visibility instantly.
**Cost** — 16.5 KB source (~3.6 KB gzip), zero dependencies. Three DOM elements, but heavy CPU cost formatting and parsing massive SVG path strings for up to 600 tiles on every animation frame. Content prerenders on server, but clip-path animation is client-only.
**Fit for ARKRETE** — No fit. Novelty mosaic pixel dissolves and spinning square wipes degrade architectural photography and look like video game transitions.
**Verdict** — skip — arcade mosaic wipe that burns CPU generating giant clip-path strings and ruins architectural photography.
