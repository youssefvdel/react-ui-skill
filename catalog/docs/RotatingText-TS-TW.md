# RotatingText
**Registry**: `RotatingText-TS-TW` · **Deps**: motion@^12.23.12 · **Files**: RotatingText/RotatingText.tsx
**What it does** — Cycles a list of phrases on a timer, animating each grapheme in and out with slide, 3D flip, blur, scale or drop while the container springs to the width of the text. A highlight mode wraps the phrase in a coloured block that resizes to fit the current word.
**Props** — `texts` (string[], required) — the phrases; `effect` ('slide' | 'flip' | 'blur' | 'scale' | 'drop', slide) — how characters swap; `rotationInterval` (2000ms) — time per phrase; `staggerDuration` (0s) — per-character delay; `staggerFrom` ('first' | 'last' | 'center' | 'random' | number, first) — where the stagger starts; `highlight` (false) — coloured block behind the text; `highlightColor` ('#a855f7') — that block's colour; `pauseOnHover` (false) — holds the current phrase.
**Motion** — Time-triggered: a timeout swaps the phrase through AnimatePresence in wait mode, each character its own motion.span on a spring or tween, exit offset from enter. Layout springs animate width; `MotionConfig reducedMotion="user"` strips the transforms so reduced motion gets a plain text swap. Exposes next / previous / jumpTo / reset through a ref.
**Cost** — Pulls the whole motion/react runtime, ~35–40 KB gzip, for one line of text; one span per character, doubled during the overlap, plus a layout-animated parent. Client-only for the animation; SSR renders the first phrase, so prerendered HTML is correct but rotates only after hydration.
**Fit for ARKRETE** — home, the line under the monument wordmark — the one place a rotating phrase could go. It is still wrong there: the wordmark is carved and fixed, and a phrase that keeps flipping is the opposite of carved.
**Verdict** — skip — the highlight block is a second accent by construction, and a full motion runtime for one changing word does not earn its place.
